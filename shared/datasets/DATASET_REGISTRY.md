This registry lists the **public datasets that CLBG Intelligence Track assessments may reference by ID** (`DSET-NNN` in an assessment's `metadata.yaml`). Every entry records where the data comes from, the exact licence or terms found on the provider's own page or API, the known limitations an assessor should expect candidates to discover, and the units it suits.

**Status meanings**

- **RECOMMENDED**: an explicit, permissive or education-compatible licence was confirmed from the provider. Use freely, with attribution as the licence requires.
- **CONDITIONAL**: usable, but with an obligation the assessment must state. Examples: non-commercial-only terms, gated access, per-source licences, no published licence (download from source, never redistribute), or a licence conflict between the original and a mirror. The assessment README must repeat the condition.
- **NOT RECOMMENDED**: the terms are unclear, unverifiable, or the domain carries risks that have not been reviewed. Do not use in assessments until the entry is re-verified and upgraded.

**Verified? column.** "Y (date)" means the licence/terms text was read on the provider's page or API on that date. "N: reason" means it could not be confirmed. Where a page was reachable but publishes *no* licence, the entry is marked N with that reason; the absence was confirmed, the licence was not.

## 1. Selection criteria

A dataset enters the registry only if **all** of the following hold:

1. **Lawful to use for non-commercial education.** An explicit open licence (CC0, CC BY, CC BY-SA, ODbL, MIT, BSD, Apache-2.0, CC BY-IGO) or explicit education/research terms. CLBG's assessment use is non-commercial, so NC licences are acceptable but are flagged CONDITIONAL.
2. **Free to obtain.** No payment; at most a free account. Gated or registration-only sources are CONDITIONAL and never the *only* path through an assessment.
3. **Feasible on member hardware.** The working subset must fit a CPU-only laptop with 8 GB RAM, or a free Colab/Kaggle tier. Large datasets are listed only with a stated subset strategy (one month of TLC data, val2017 of COCO, one language of FLEURS).
4. **Assessment value.** The data has a real question behind it and realistic imperfections (missing values, leakage traps, shift, imbalance) that test judgement, not just syntax.
5. **Diversity.** Across the registry: tabular, relational, time series, geospatial, text, speech, image and multimodal; finance, agriculture, energy, health infrastructure, transport, retail, language and science.
6. **African and Nigerian relevance where it exists.** Masakhane and HausaNLP language resources, NBS, HDX/GRID3 Nigeria layers, WFP Nigeria food prices, World Bank and FAOSTAT country panels, NASA POWER and Open-Meteo for Nigerian coordinates.
7. **Over-familiar benchmarks are de-prioritised.** Iris, Titanic and house prices are excluded by the authoring guide. MNIST-class benchmarks (Fashion-MNIST, CIFAR-10) are listed for controlled engineering experiments only, never as the headline problem.

## 2. Verification procedure (manual re-verification checklist)

Re-verify every entry at least once every 12 months (the dataset validator warns after 365 days), and **always** before an assessment cycle opens. For each entry:

- [ ] **Open the URL** in the registry. Confirm it resolves (HTTP 200) to the provider's own page, not a mirror. Follow redirects and update the URL if it moved permanently (for example, CIFAR now redirects to `cave.cs.toronto.edu`).
- [ ] **Find the licence text on the provider page or API**, not on a third-party mirror. Useful machine checks:
  - Hugging Face: `https://huggingface.co/api/datasets/<org>/<name>` (look at `cardData.license`, `tags` and `gated`), then read the card's "Licensing Information" section.
  - HDX: `https://data.humdata.org/api/3/action/package_show?id=<name>` (`license_title`).
  - Zenodo: `https://zenodo.org/api/records/<id>` (`metadata.license`).
  - OpenML: `https://www.openml.org/api/v1/json/data/<id>` (`licence`, `original_data_url`).
  - UCI: the dataset page shows a licence badge (all entries here are CC BY 4.0).
  - Kaggle: the dataset page metadata (`license.name`).
- [ ] **Copy the licence wording exactly** into `license`. If the original and a mirror disagree, record both and apply the **most restrictive** reading (e.g. NaijaSenti: CC BY 4.0 on GitHub vs CC BY-NC-SA 4.0 on Hugging Face).
- [ ] **Check access conditions**: account, gating, API key, rate limits, non-commercial endpoints, terms acceptance. Record them in `notes`.
- [ ] **Check size and format** against the current release, and note version/date if the provider versions the data.
- [ ] **Screen for personal data.** Does the dataset identify or profile people (usernames, voices, faces, addresses, health or financial records)? If so, apply §3 and record the mitigation.
- [ ] **Re-check known limitations.** Have new issues been published (label errors, withdrawal, contamination of LLM benchmarks)? Has the dataset been deprecated or taken down (as Common Voice moved off Hugging Face in October 2025)?
- [ ] **Update `verified`, `verified_on` and the status prefix in `notes`** in `registry.yaml`, then regenerate the tables in this file so the two stay identical.
- [ ] **Run the validators** from the repository root: `python tools/dataset-validator/validate_datasets.py` and `python tools/assessment-validator/validate.py`.
- [ ] **If the terms worsened**, downgrade the status, list every assessment whose `metadata.yaml` cites the ID, and open an issue for each affected unit owner.

Never mark an entry verified from memory, a blog post, a search snippet or a third-party mirror alone.

## 3. Privacy notes (Nigeria Data Protection Act 2023)

CLBG is a Nigerian student community, so assessments that touch personal data fall under the **Nigeria Data Protection Act 2023 (NDPA)** and guidance from the Nigeria Data Protection Commission (NDPC). Assessment authors and assessors must apply these rules:

1. **Data minimisation.** Use the smallest subset that serves the learning objective. Drop identifiers you do not need (tweet IDs, usernames, user IDs, free-text addresses) at load time.
2. **No re-identification.** Candidates must not attempt to identify individuals in any dataset. That includes linking MovieLens users, Common Voice or AfriSpeech speakers, GH Archive accounts or tweet authors to real people. Attempting it is an integrity violation, and several providers' terms forbid it outright.
3. **Sensitive personal data.** Health, financial, biometric (voice, face), religious, ethnic and criminal-justice data are high-risk categories. Prefer synthetic data or properly de-identified public releases, and add safeguards. Where a real dataset is used (e.g. credit default, AfriSpeech), the assessment explains why and what is forbidden.
4. **Social-media text** (NaijaSenti, AfriSenti, emotion). Strip `@handles` and URLs before display. Never republish raw tweets in submissions or reports. Quote at most short, de-identified excerpts.
5. **Member-sourced data.** If an assessment lets members collect their own data (scraping, surveys, WhatsApp exports), it must require a lawful basis (usually consent), a privacy notice, de-identification before submission, and deletion after marking. Data about other students is off-limits without documented consent.
6. **No personal data in submissions or the public repo.** Submissions must not contain raw personal data. CLBG repositories must not carry personal contact details of staff or members.
7. **API keys and credentials** (OpenAQ, Kaggle, Hugging Face tokens) are personal secrets. They go in environment variables or `.env` files excluded by `.gitignore`, never in notebooks or commits.
8. **Cross-border transfer.** Uploading personal data to foreign cloud services (including LLM APIs) is a transfer under the NDPA. Assessments involving LLMs must use synthetic or public non-personal data, or a local model.

## 4. Synthetic data policy

CLBG assessments use **deterministic synthetic data instead of a registry dataset** when any of the following applies:

| Situation | Why synthetic | Example |
|---|---|---|
| The subject is personal or sensitive (health records, mobile-money transactions, student records, payroll) | NDPA risk; no lawful public source | Synthetic clinic visit logs; mobile-money transfer ledger |
| The assessment needs a **known ground truth** to grade against | Real data rarely has a known causal effect, injected anomaly, or planted defect | Semi-synthetic uplift data with a true treatment effect; a registry with planted duplicates |
| **Integrity**: answers must not be searchable | Public datasets have public solutions | Re-seeded hidden-test variants |
| Hidden tests must use **held-out or re-seeded** data | Hard-coding must fail | Same generator, different seed in the assessor kit |
| No suitable licensed public dataset exists for a Nigerian context | Licences unclear or data unpublished | Generator diesel consumption for a hostel; Lagos danfo route timings |
| The real dataset is too large for 8 GB RAM / CPU | Feasibility | A down-scaled synthetic replica of a public schema |
| AI Engineering tests need **reproducible LLM behaviour** | Real APIs are non-deterministic and paid | Deterministic mock model and tool responses |

**Rules for generators**

1. **Deterministic.** The CLI is `--out DIR --seed INT`, and the same seed produces byte-identical output. `tools/dataset-validator` runs each generator twice and compares hashes.
2. **Fictional people only.** Names from a mixed, culturally plausible pool; emails at `example.ng`; phone numbers in a reserved, clearly fake pattern; no real BVN/NIN formats with valid checksums; no real addresses below LGA level.
3. **Documented.** Each generator ships with a data card covering variables, the generative process, deliberately injected defects (only in the assessor kit if revealing them would give answers away), known differences from reality, and the seed used for the public copy.
4. **Realistic enough to require judgement.** Include missingness, skew, seasonality, shift or noise matching the learning goal. Avoid perfectly clean data unless cleanliness is the point.
5. **Small when committed.** Generated files committed to the repo stay under 2 MB. Anything larger is generated at setup.
6. **Grounded where possible.** Calibrate marginal distributions against a registry dataset (e.g. price levels from DSET-027, irradiance from DSET-022) and cite it in the data card.
7. **Never presented as real.** Every synthetic file and README states that the data is synthetic.

## 7. Adding a dataset

Unit authors propose new entries in `shared/datasets/proposals/<UNIT>.yaml`, using their reserved ID range and the same keys as `registry.yaml`. A committee reviewer repeats the §2 checklist before merging an entry here. Never fabricate a URL, licence or size. If something cannot be confirmed, set `verified: false` and say why.
