# Cross-Disciplinary Assessments

Some competencies belong to **every** subtrack: programming, version control, mathematics, testing, technical writing and responsible technology. Others only show up when the subtracks **work together**, for example when an analysis informs a model, which in turn powers an AI product. This collection assesses both.

| Collection | Purpose | Counts toward |
|---|---|---|
| [Foundations](foundations/) (`XD-FND`) | Shared foundation assessments, each with **subtrack-specific extensions**: you do the shared core plus the extension for your subtrack. | Tier 1 evidence in the subtrack whose extension you complete |
| [Integrated challenges](integrated-challenges/) (`XD-INT`) | Pair or team projects that need two or three subtracks to collaborate through clear interfaces (data contracts, model APIs, evaluation protocols). | Tier 2 evidence for each member, in their own subtrack, judged on their contribution |
| [Advanced challenges](advanced-challenges/) (`XD-ADV`) | Ambiguous, research-grade, multi-discipline problems. | Tier 3 evidence (double-marked) |

**Why not duplicate foundations in every subtrack?** Writing the same "Python basics" assessment three times would waste members' time and make the subtracks less distinct. Instead, each shared core assesses the common skill once, and a short extension shows how it is used in *your* discipline. The [research report](../docs/research/RESEARCH_AND_STANDARDS_REPORT.md) discusses this choice.

**Team assessments.** Every member submits a contribution statement, and every member must defend the **whole** system, with extra depth on their own part. See [assessment policy §6](../docs/assessment-policy.md#6-collaboration).
