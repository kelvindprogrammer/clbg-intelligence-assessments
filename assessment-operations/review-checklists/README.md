# Review Checklists

## A. Submission review (assessors)

- [ ] The commit SHA, ID and version are recorded, and conflicts of interest are declared.
- [ ] Clean-environment rebuild, run following the member's README only.
- [ ] Key results reproduce (and tolerances are noted).
- [ ] Public, member and hidden tests have been run, and their output saved.
- [ ] `AI_USE_AND_SOURCES.md` is present and plausible.
- [ ] No secrets or personal data in the repository. Spot-check with `git log -p | grep -iE "api[_-]?key|secret|password|token"`.
- [ ] Every rubric dimension is scored with one line of evidence.
- [ ] Defence run using the kit's script, with notes recorded.
- [ ] Gates applied, and the outcome decided by the placement framework.
- [ ] Double marking requested where required.
- [ ] Feedback meets the standard: two strengths, prioritised next steps.
- [ ] Placement record updated.

## B. Data Science specifics
- [ ] Data provenance and licence are acknowledged.
- [ ] Every quoted number is regenerated by the code.
- [ ] Uncertainty is quantified where claims are made.
- [ ] Alternative explanations or confounders are considered.
- [ ] Visualisations are honest (scales, baselines, encodings).

## C. ML Engineering specifics
- [ ] The split and validation design match the data structure (no leakage across groups or time).
- [ ] Baselines are present and meaningful.
- [ ] Metrics match the problem's costs. Calibration is checked where probabilities matter.
- [ ] Hyperparameters are tuned on validation data only, and the test set is used once.
- [ ] Results are reported with variation (seeds, folds).
- [ ] Error analysis exists and informs conclusions.

## D. AI Engineering specifics
- [ ] There are no secrets in code or history, and keys come from the environment.
- [ ] A free or local or mock path works. The tests don't need paid APIs.
- [ ] The evaluation set exists, and evaluation is separated per component (retrieval vs generation).
- [ ] Prompt injection and untrusted-content handling are considered, with tests where required.
- [ ] Tools are least-privilege, consequential actions need human approval, and code execution is sandboxed.
- [ ] Cost and latency are measured where relevant.
